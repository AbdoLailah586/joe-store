# Installation and offline browsing

JOE Store is an installable PWA on the existing Vercel origin. The manifest provides a stable app identity, 192/512 PNG icons, a separate maskable icon, standalone display and public catalog/wishlist shortcuts. No store account or app-store package is required to install it.

Chrome controls install eligibility and timing. Once it supplies `beforeinstallprompt`, the site offers a dismissible invitation. Its Install button opens the browser's own dialog on a user click, consumes that event only once, and waits for `appinstalled` before confirming installation. A permanent footer button gives manual instructions when the native event is unavailable; iPhone/iPad instructions use Safari. Installed standalone windows hide the invitation. Dismissing the invitation snoozes only the custom banner for seven days.

The production build generates `dist/sw.js` from `pwa/service-worker.template.js`, using a content-derived version and every built JS/CSS chunk. It precaches the public application shell, manifest, icons and offline page. API paths, POSTs and cross-origin requests are never intercepted or cached. Previously fetched same-origin product photos are cached with a 100-image and 2 MB per-image bound. Other photos still require a connection. Incomplete precaching rejects worker installation. The current and preceding shell remain available for tabs using older hashed chunks; only this application's superseded caches are cleaned up.

The complete catalog is saved separately in IndexedDB using an explicit public field projection. Hidden products, wholesale costs, original inventory rows and unknown fields are excluded. Failure to access IndexedDB does not crash browsing. A failed live load restores the saved catalog, displays its timestamp, and disables report readiness, checkout submission and administration. Carts and wishlists remain local; failed/offline orders are never queued or submitted automatically. Reconnecting or retrying reloads live prices and stock before orders can be confirmed. No API login/session, customer address, order, message or admin permission response is added to the offline cache.

Users must first visit while connected and wait for the footer's offline-ready status. Clearing browser data or browser storage eviction removes the saved offline copy. A new worker waits until existing tabs close or the user chooses Update app; it does not automatically reload a checkout form.

Verification includes manifest/icon dimensions, hosting route exclusions, browser prompt lifecycle, worker navigation fallback, private API exclusion, image cache bounds, multi-tab asset retention, public-only catalog projection and offline checkout refusal. `scripts/qa_pwa_server.mjs` serves a read-only production build: it proxies only anonymous catalog reads and suppresses all writes. Browser QA warms the complete catalog, stops this server, reloads a direct catalog URL and searches the saved 2,245 products while offline. It also checks the offline administration guard and native dialog fallback.

References: [Chrome install criteria](https://web.dev/articles/install-criteria), [install prompts](https://web.dev/learn/pwa/installation-prompt).
